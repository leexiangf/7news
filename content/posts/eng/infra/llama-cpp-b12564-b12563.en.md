llama.cpp cut two pre-release build tags on **20 Nov 2026**. The one operators should actually schedule around is **b12563**’s precision fix; **b12564**, minutes later, is an Orin MMVQ micro-opt. No causal link—just adjacent commits on a high-frequency stream.

## b12563: why the per-expert fallback dropped precision

Release notes (PR [#31345](https://github.com/ggml-org/llama.cpp/pull/31345)) state that the per-expert `dst_slice` kept `op = GGML_OP_NONE`, so `ggml_prec_get_acc` returned **UNDEFINED** and a requested accumulation precision was ignored. This build sets the slice op to **`GGML_OP_MUL_MAT`**. The notes also **revert** an earlier “fp32 result buffer for quantized src0” approach and remove those tests—the final fix is “correct op,” not a different output dtype.

## Which CUDA path blew up into inf

| Stage | Behavior |
| --- | --- |
| IQ1_M expert weights | No MMQ kernel |
| Small batches | MMVQ |
| Past MMVQ batch limit | dequantize + cuBLAS |
| Test magnitude | ~**1.3e5**, above fp16 max **65504** |
| Old fp16 result buffer | **inf**, then **NaN** in the next layer |
| CPU reference | Stays finite—easy to diff |

The cited field case is **gpt-oss-120b** with IQ1_M experts at `-ub 512` ([#30951](https://github.com/ggml-org/llama.cpp/issues/30951)). New tests are **CUDA-only**: Vulkan at default precision deliberately accumulates quantized matmuls in fp16 and would fail them by design.

## b12564: Orin single-column MMVQ

**b12564** (PR [#31268](https://github.com/ggml-org/llama.cpp/pull/31268)) optimizes CUDA Orin single-column MMVQ and adds a dedicated Orin branch in `calc_rows_per_block`. Independent of the precision story: non-Orin fleets need not schedule for 64 alone, but mainline binary consumers usually pick up both tags together.

## How to verify after upgrade

1. Confirm build ≥ **b12563** (or includes #31345).  
2. Re-run **IQ1_M / large `-ub`** CUDA loads that used to exceed 65504 intermediates; outputs should stay finite.  
3. Diff against a **CPU reference** on the same model and flags.  
4. Do not use Vulkan’s default-precision path to “validate” these CUDA cases—the notes say it does not apply.

Most tags in this stream are noise; **b12563** is the rare one that turns intermittent NaNs into an explainable engineering defect. Orin users can also confirm **b12564** landed in their artifact channel.
